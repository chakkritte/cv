03. EDA Intro

What is EDA? — 5 Questions It Answers

Exploratory Data Analysis (EDA) is the first step after loading data. Before building any model, EDA reveals the shape, quality, and hidden patterns of your dataset — answering five core questions:

straighten
Shape?
How many rows & columns? What are the types?
block
Missing?
Which columns have nulls? What fraction?
warning
Outliers?
Are there extreme values or sensor faults?
hub
Correlates?
Which features move together?
lightbulb
Story?
What hypotheses emerge from the patterns?
tips_and_updates

John Tukey coined EDA in 1977: "It is important to understand what you CAN DO before you learn to measure how well you SEEM to have done it." EDA is about asking questions, not confirming hypotheses — use it to discover what questions to ask next.

09. Missing Data

Missing Data — Three Mechanisms

MCAR

Missing Completely At Random

The missing-ness is unrelated to any data, observed or unobserved. Like a sensor cable randomly disconnected.

Example: pm25 dropout due to random power cuts
→ Safe to drop or impute with mean
MAR

Missing At Random

Missing-ness depends on other observed variables. Predictable but not on the missing value itself.

Example: co2 missing only from station BKK-03 (old firmware)
→ Group imputation by station
MNAR

Missing Not At Random

Missing-ness depends on the value itself (unobserved). The trickiest — simple imputation introduces bias.

Example: AQI sensors go offline when PM2.5 > 200 (overloaded)
→ Domain knowledge required
tips_and_updates

In practice, you often can't be certain which mechanism applies. Use domain knowledge: ask "Is the sensor likely to fail more in certain conditions?" If yes, suspect MAR or MNAR. Use Little's MCAR test for statistical confirmation.

12. Drop vs Impute

Drop vs Impute — Decision Framework

delete When to DROP

  • Column >50% missing (no signal left)
  • Row with multiple nulls in key columns
  • MNAR and imputing would bias the model
  • Large dataset — losing a few rows doesn't matter
df.dropna(subset=['aqi'])
df.dropna(thresh=5)

healing When to IMPUTE

  • Column <5% missing and MCAR
  • Time-series gap (use forward-fill)
  • Small dataset — every row counts
  • MAR — can predict from other columns
df['pm25'].fillna(
    df['pm25'].median())

13. Imputation

Imputation Strategies

calculate

Mean Imputation

numeric

Replace nulls with the column mean. Simple but sensitive to outliers — the mean gets pulled toward extremes.

df['pm25'].fillna(
    df['pm25'].mean())
horizontal_rule

Median Imputation

skewed data

Robust to outliers. Use when data is skewed or has extremes. Better choice for AQI / sensor data.

df['aqi'].fillna(
    df['aqi'].median())
category

Mode Imputation

categorical

For categorical columns, use the most frequent category. Makes sense when one category dominates.

df['station'].fillna(
    df['station'].mode()[0])
trending_up

Forward Fill (ffill)

time-series

Propagate the last known value forward. Ideal for sensor time-series where readings change slowly.

df['pm25'].fillna(
    method='ffill')
# or: df.ffill()

# 2. Drop columns >50% missing

    pct > 0.5].index)

16. Outliers

Why Outliers Matter

An outlier is a data point that lies far from the main cluster. In smart-city sensor data, outliers are common and have two very different causes:

Sensor faults / artefacts
AQI = 999 when sensor overloads; PM2.5 = 0.0 when sensor disconnects. Should be removed or replaced.
Real extreme events
AQI = 350 during a dust storm or wildfire — unusual but real. Should be kept; they're what you're trying to detect.
Impact on statistics & models
Mean
One AQI=999 shifts the mean from 86 to 127 — a 48% distortion from a single row.
Regression
Linear regression minimises squared error — outliers dominate and pull the slope toward them.
Clustering
K-Means centroids shift toward outliers, creating meaningless clusters.
Scaling
MinMaxScaler compresses all normal values to 0.00–0.01 if max=999. Use RobustScaler instead.
17. IQR Method

Outlier Detection — IQR Method

$$IQR = Q_3 - Q_1$$
$$ ext{Lower fence} = Q_1 - 1.5 imes IQR$$
$$ ext{Upper fence} = Q_3 + 1.5 imes IQR$$
Applied to AQI column:
Q1 = 62, Q3 = 106
IQR = 106 − 62 = 44
Lower = 62 − 1.5 × 44 = −4
Upper = 106 + 1.5 × 44 = 172
AQI = 999 → flagged outlier ✓
Q1 = df['aqi'].quantile(0.25)
Q3 = df['aqi'].quantile(0.75)
IQR = Q3 - Q1
mask = (df['aqi'] < Q1 - 1.5*IQR) |        (df['aqi'] > Q3 + 1.5*IQR)
outliers = df[mask]
Why 1.5×IQR?

Tukey's fence. For a normal distribution, 1.5×IQR captures 99.3% of data within the fences — so only ~0.7% are flagged as outliers by chance. Use 3×IQR for very conservative detection (extreme outliers only).

Advantages of IQR
  • Robust: Q1 and Q3 are not affected by outliers themselves
  • Non-parametric: works on any distribution
  • Easy to explain to non-statisticians
  • Assumes unimodal distribution — bimodal may over-flag
18. Z-Score

Outlier Detection — Z-Score Method

$$z = rac{x - \mu}{\sigma}$$
Interpretation
z = 0 → exactly at the mean
z = 1 → one std dev above
z = −1 → one std dev below
|z| > 3 → outlier flag (3σ rule)
from scipy import stats

z = np.abs(stats.zscore(
    df['aqi'].dropna()))
outliers = df[z > 3]
print(f"Outliers: {len(outliers)}")

# Or with numpy
mu = df['aqi'].mean()
sigma = df['aqi'].std()
mask = (df['aqi']-mu).abs() > 3*sigma
IQR vs Z-Score — When to use which
PropertyIQRZ-Score
DistributionAnyNormal preferred
Robust to outliersYesNo (mean/std shift)
Small datasetsOKBetter
Threshold1.5 / 3 × IQR|z| > 2 or 3
For AQI data: prefer IQR

AQI is right-skewed (long upper tail). Z-score uses mean and std which are both distorted by the 999-outlier. IQR is median-based and immune to this distortion.

20. Treatment

Outlier Treatment Strategies

delete

Remove

Drop rows where values are clearly sensor faults. Use when you are certain the value is erroneous (AQI = 999).

df = df[df['aqi']
        .between(0, 500)]
⚠ Loses rows permanently
compress

Cap (Winsorise)

Clip extreme values to the fence values. Preserves the row while limiting the outlier's influence. Best for modelling.

upper = Q3 + 1.5*IQR
df['aqi'] = df['aqi'].clip(
    upper=upper)
✓ Keeps all rows
functions

Transform

Log or sqrt transform compresses the right tail. Makes skewed distributions more normal, reducing outlier impact naturally.

df['aqi_log'] = np.log1p(
    df['aqi'])
Requires back-transform
Decision guide for AQI data
AQI = 999 → sensor fault → remove. AQI = 480 during wildfire → real extreme event → keep. When unsure whether it's real: cap to preserve the row while limiting model distortion. Document every decision.

Shape characteristics
Normal (Symmetric)
Mean ≈ Median ≈ Mode. Bell curve. Temperature, IQ, measurement errors.
Right-Skewed (Positive skew)
Mean > Median. Long right tail. AQI, income, sensor spikes. → Use log transform.
Bimodal (Two peaks)

29. Scaling

Feature Scaling — StandardScaler vs MinMaxScaler

$$\text{Standard: } z = \frac{x - \mu}{\sigma}$$
$$\text{MinMax: } x' = \frac{x - x_{min}}{x_{max} - x_{min}}$$
scaling.py 
from sklearn.preprocessing import (
    StandardScaler, MinMaxScaler)

# Always fit on TRAIN only
ss = StandardScaler()
X_train_std = ss.fit_transform(X_train)
X_test_std  = ss.transform(X_test)

mm = MinMaxScaler()
X_train_mm = mm.fit_transform(X_train)
X_test_mm  = mm.transform(X_test)
PropertyStandardScalerMinMaxScaler
Output rangemean=0, std=10 to 1
Outlier impactModerateSevere
Best forSVM, LR, PCANeural nets, KNN
Preserves zerosNoYes
Never fit on the full dataset!

Fitting scaler on training + test leaks test statistics into training. Always fit_transform on train, transform only on test.

When outliers exist → RobustScaler
from sklearn.preprocessing \
    import RobustScaler

31. Log Transform

Log & Box-Cox — Taming Skewed Data

$$x' = \log(1 + x) \quad \text{(np.log1p)}$$
$$x'(\lambda) = \begin{cases} \frac{x^\lambda - 1}{\lambda} & \lambda \neq 0 \\ \log x & \lambda = 0 \end{cases}$$
transform.py 
# Log transform (handles zeros)
df['aqi_log'] = np.log1p(df['aqi'])

# Square root (milder)
df['pm25_sqrt'] = np.sqrt(df['pm25'])

# Box-Cox (auto-selects lambda)
from scipy.stats import boxcox
df['aqi_bc'], lam = boxcox(
    df['aqi'] + 1)
print(f"Lambda: {lam:.3f}")

# Invert after prediction
y_pred_orig = np.expm1(y_pred_log)

pct = df_clean.isnull().mean()

num = df_clean.select_dtypes('number')

# === 5. OUTLIERS (IQR) ===
for col in num.columns:
    Q1 = df_clean[col].quantile(0.25)
    Q3 = df_clean[col].quantile(0.75)
    IQR = Q3 - Q1
    df_clean[col] = df_clean[col].clip(
        Q1-1.5*IQR, Q3+1.5*IQR)

34. Case Study

Smart City Case Study — Bangkok AQI EDA

Problem Statement

The Bangkok Metropolitan Administration operates 30 AQI sensors across 10 districts. Data engineers have dumped one year of readings (8,640 hourly rows per sensor) into a single CSV. Before building a next-hour AQI predictor, you must EDA the data.

Key findings from EDA
01 Station BKK-07 has 31% missing PM2.5 → old sensor
02 AQI peaks 7–9am and 5–8pm (rush hour)
03 PM2.5 ↔ AQI correlation = 0.91 (strongest predictor)
04 3 rows with AQI=999 (sentinel value for sensor overload)
05 AQI is right-skewed (skew=4.8) → log transform needed
Decisions taken
BKK-07 Drop station — 31% missing PM2.5 is beyond repair
Nulls Forward-fill other sensors (time-series gap, MCAR)
999 Remove rows where AQI > 500 (physically impossible)
Scale log1p(AQI) then StandardScaler for model input
Takeaway

Every EDA decision requires a reason. Document why you dropped, imputed, or transformed. These decisions directly affect model fairness and accuracy.

tips_and_updates

Automated tools are great for a first pass — they catch the obvious quickly. But they can't replace domain knowledge. A profiling report won't know that AQI=999 is a sensor fault rather than a real extreme event. Always follow up with targeted analysis.
